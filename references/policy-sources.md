## 取源通道属性与困难源兜底（2026-09-29 / 09-30 实测）

政策原文的"可达性"因发文方式和渠道而异，取源前需知道以下属性：

| 通道 | 实测属性 | 处置 |
|:-----|:---------|:-----|
| 部委官微（首发） | **联合发文常由主管部委官微首发**，官网 `xxgk`/`zs` 政策文件库与 gov.cn 政策库滞后上线、甚至长期不收录 | 若坚持等官方原文页取 `source_url`，会受 10 天窗口限制而**漏档**；需按窗口全量扫描，勿等 |
| 工信部通知页 | 浏览器直读可用（含 gov.cn 政策库未收条目） | 走 `browser_navigate` 兜底，不依赖列表页爬取 |
| 网信办 / 人社部 / 交通运输部 | 无正文可读 | 转中央政策文件库 + `web_search` 交叉，入库前开原页核验主体 |
| gov.cn 政策库 | 403 / 静默空响应（09-30 实测 403×2） | **常态告警非故障**；补查用 `gov_library_search.py` 逐词扫全窗口，优于 `web_search` |

**实例（2026-09-29）**：交通运输部等十二部门《推动多式联运高质量发展 优化调整运输结构攻坚行动方案（2026—2030年）》由交通运输部官微首发，`xxgk.mot.gov.cn`、`zs.mot.gov.cn` 政策文件库与 gov.cn 政策库**均无原文页** → 无法取得官方 `source_url`（原文摘要见 fact_store #372）。

**两个待定口径**（切莫自行放宽）：
1. 正文含"人工智能/数智化"专章但标题未中主题白名单时，是否引入"正文专章即放行"的二级判据（现口径纯看标题）。
2. 官微首发、官网原文页滞后时，入库取源用官微/权威转载暂代，还是等原文页（等则受 10 天窗口限制，逾期即漏档）。

## 主题门禁口径（中央文件旁路已落地）

**现行口径**：门禁三层判定 —— ① 程序/事务类文书直接主题外（含**申报/推荐/征集/遴选/评选类工作通知**，2026-10-16 D5-B）；② 中央/国务院（含办公厅）发文、网信系统（中央网信办 / 国家互联网信息办公室）发文直接主题内；③ 其余按标题关键词白名单（含「网信 / 网络强国 / 个人信息保护 / 关键信息基础设施 / 电子信息 / 传统制造业 / 策源地 / 创新型产业 / 创新中心 / 创新平台 / 创新集群 / 创新基地 / 创新联合体」）判定。

- 起因：综合性中央文件的标题不含数字化词，纯白名单会系统性判为「主题外」（实例：《中共中央 国务院关于发展新质生产力的意见》——正文含「人工智能+」行动、实体经济与数字经济融合，属主题核心载体，曾靠人工 `--allow-title` 救回）。
- **旁路必须带排除项**：名单 / 公示 / 遴选 / 认定 / 备案 / 征求意见类事务文书**不走旁路**，否则中央级的名单类公告会随之涌入。层的顺序即口径：先挡程序类 → 再走旁路 → 最后才是白名单。
- **文件类型边界（2026-10-16 D6 拍板）**：**框架 / 白皮书 / 标准 / 技术指南 / 研究报告类发布物属收录范围**——它们多是一手材料、政策方向性强（实例：网安标委会《人工智能安全治理框架3.0》，网信办指导），不收会长期缺档。入库时在条目里标 `doc_type`（`framework` / `whitepaper` / `standard` / `guideline` / `report`；留空 = 普通政策文件）便于检索区分；发布主体非部委时（如标委会）`issuer` 写实际发布主体。
- 放宽只作用于**未来入库**，不回溯删除库内已有条目；改口径要同时改门禁代码、每轮跑的规则文本（cron prompt）与本文档，只改一处不算改完。
- **内容层校验（2026-10-14，2026-10-16 D1 裁定后扩大适用）**：标题只是第一层筛子。**D1 裁定：主题边界按内容判，不按发文主体宽窄**——凡标题被判主题外的**正式发文候选一律抓正文复核**（不再要求标题先含行业/领域词，因为"含数字化实质内容"只能从正文看；程序/事务类文书仍跳过，它们在第一层就被挡掉）。实现 `policy_content_probe.py`：正文命中 ≥3 个不同主题词 → 疑似误判，人工看原文后 `--allow-title` 放行；1–2 个 → 弱相关仅记录。历史漏判实例：《关于推进国有企业打造原创技术策源地的指导意见》、工信部产融合作平台高新技术企业专区上线服务通知、商务部等 7 部门《品质电商"五优"行动》（标题用简称"电商"，白名单与探针词表都没命中）。
- **可读文字层（`text_path`）**：扫描版 PDF 条目在 `local_path`（原件）之外记 `text_path`（OCR 文字层，如 457 页的“数据要素×”典型场景指引，24.9 万字）；分发包据此排除原件 PDF，包用户读文字层即可，原件仍留仓库。
- **主线相关性提示（阶段2d，2026-10-14 起，仅提示不剔除）**：对当日**即将入库**的候选与兜底补查候选跑 `policy_relevance_hint.py`——主线信号分 0 分（既不含数字化内容、也不属战略规划/主线域）的条目在日报里列出，交审核人判；门禁已挡的主题外条目不再逐条提示（只报数量）。口径实现收在 `policy_theme_gate.mainline_score`（唯一来源），**禁止**对接自动剔除、**禁止**用于存量。
- **口径的实测边界（2026-10-14 用用户点名的 18 条剔除项反推验证）**：主题口径**不是一条可机械复现的规则**。用「主线信号分」（数字化词 +2 / 期次规划 +1 / 主线域 +1 / 中央国家级 +1）做标尺：18 条剔除项中机械规则能识别 15 条（83%），但会把用户明确保留的 10 条一并列为候选（误伤率 12%，含《重点生态保护修复治理资金管理办法》《科技型企业孵化器政策衔接通知》《外籍个人股息红利个人所得税公告》等）。**两条零反例的硬规律**可安全固化：① 含数字化内容的条目从不被剔除（18 条里数字化命中数 = 0，保留侧 15 条）② 战略规划／"十五五"期次类从不被剔除（命中数 = 0，保留侧 32 条）。其余取舍是**逐条业务相关性判断**（主线域＝央企国资、能源电力、工业制造、交通物流、医疗、知识产权、数据要素），因此检测结论只能作为**候选清单供人工裁定**，不得对接自动剔除。
- 放宽后回归：全库重跑并报「判内 / 判外」条数变化，看新放行的逐条是否都是真修正，另跑边界用例（中央名单类、非数字类国资委文件、部委公告第 N 号）确认仍被挡。
